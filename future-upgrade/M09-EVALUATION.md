# M09：受控自适应面试与成对试验

本功能是已实现的可选试验，默认仍为 `fixed`。确定性测试通过不代表真实模型的提问质量或延迟已经优于原流程。

## 如何使用

```powershell
# 自适应模拟
uv run jobhunt interview --flow adaptive --company 示例企业 --target-role 前端开发 --jd "React 与可访问性"

# 自适应训练：允许请求提示和重新作答
uv run jobhunt interview --flow adaptive --mode practice --company 示例企业 --target-role 前端开发

# 恢复：沿用原事实快照、流程和预算，不重新指定这些参数
uv run jobhunt interview --resume-session <session_id>

# 离线查看结果与指标
uv run jobhunt interview-sessions show <session_id>
```

生成命令使用本机配置的模型；查看和对比不请求外部服务。回到旧体验时新建 `--flow fixed` 会话，已有会话不隐式换流程或供应商。

## 程序与模型分别决定什么

| 模型可选动作 | 程序约束 |
| --- | --- |
| 澄清、追问 | 根据上一回答判断必要性，连续次数受限；不要求问满上限 |
| 换阶段 | 只进入程序指定的下一阶段，不能跳过覆盖路标 |
| 回答反问、结束 | 正常结束动作仅在最后反问阶段允许；用户结束指令始终可用 |
| 提示、重答 | 只在训练模式允许，原回答不会被抹掉 |

仍保留 `/next`、`/pause`、`/retry`、`/finish`。达到追问上限，或剩余轮数刚够后续阶段时，优先换阶段。达到全局轮数、有效时长或请求预算时，由程序结束并保存回答；未观察到的内容不能被补成能力评分。

正常一轮只调用一次结构化生成，不串联评分器或第二个面试官。动作、阶段和完整问题经校验后先原子保存，再返回正文；拒绝、截断、重复问题和越界动作均不会推进正式阶段。自适应不展示未校验的 JSON 片段，因此首个可读正文通常要等整轮结果。原流式流程继续可选。

重复检查覆盖标准化后的相同文本，不能发现所有语义重复；单个核心问题、事实边界和追问价值仍需人工抽查。

## 默认预算

| CLI 参数 | 自适应默认 | 含义 |
| --- | ---: | --- |
| `--max-turns` | 16 | 交互轮数，含开场、提示和重答；最后反问的结束回应不新增问题轮数 |
| `--max-duration` | 1800 | 有效面试秒数，包含思考和生成，不计暂停 |
| `--max-followups` | 2 | 自适应连续追问上限 |
| `--request-budget` | 1 | 每轮最多模型 HTTP 请求，包括格式尝试和重试 |
| `--max-requests` | 32 | 整场问答请求上限，复盘另计 |
| `--request-timeout` | 30 | 单轮生成限时，秒 |

M08 的全局配置仍可进一步收紧每轮预算。默认单次请求不够完成格式适配时，本轮明确失败；不支持的格式已进入能力缓存，可显式重试。也可为新会话适度增加 `--request-budget`，所有请求仍计入整场上限。不会自动无限修复或重问。

限时在提交回答和生成期间检查，不在用户输入期间启动后台计时线程。超时仍保留已接受回答；网络读取的即时中断能力受底层 HTTP 超时约束。

## 公平比较两种流程

先保持模型设置、候选人档案、JD、风格、模拟/训练模式和回答素材一致。显式指定共有预算，原流程也会执行这些限制。例如分别开始：

```powershell
uv run jobhunt interview --flow fixed --company 示例企业 --target-role 前端开发 --jd "React 与可访问性" --max-turns 10 --max-duration 600 --request-budget 1 --max-requests 16 --request-timeout 30

uv run jobhunt interview --flow adaptive --company 示例企业 --target-role 前端开发 --jd "React 与可访问性" --max-turns 10 --max-duration 600 --request-budget 1 --max-requests 16 --request-timeout 30

uv run jobhunt interview-sessions compare <fixed_id> --with-session <adaptive_id>
```

对比器核对快照、岗位/JD、风格、模式、回答文本、模型身份及共有预算字段；模型身份缺失时返回未知。它不能证明端点背后的模型版本没变化，也不能代替检查采样参数、输出 token 预算等模型配置。两场应在这些设置保持一致时运行。固定阶段的原有追问规则与自适应追问上限是待比较差异，不作为共有预算。

实际问题不同，无法自然使用同一回答时，应记录差异而不强行认定可比。可以先用固定的合成答题素材复核调用链，再用真实交互检查使用体验。

### 指标解释

| 字段 | 能说明什么 |
| --- | --- |
| `known_model_requests` | 已观测的问答 HTTP 请求次数，包含失败和格式尝试；不含复盘 |
| `unknown_request_upper_bound` | 崩溃遗留请求可能消耗的保守上界，不冒充实测扣费数 |
| `generation_attempts` / `failure_rate` | 已开始生成及中断尝试的失败情况；包括不合格动作等业务拒绝 |
| `retry_count` | 同一请求的显式再尝试，完整结果回放不会增加 |
| `request_elapsed_seconds` | 服务处理请求的累计耗时 |
| `first_text_seconds_median` | 每个请求最近一次尝试的可读文本就绪延迟中位数；进度提示不计入 |
| `unmeasured_legacy_requests` | 旧记录或中断记录缺少测量的条数，不能当零延迟或零调用 |

延迟以服务侧取得可显示文本为准，不等同用户屏幕上的端到端时间；原子写盘、宿主网络和渲染仍可能增加时间。失败和重试的耗时保留在累计值中。合成替身的时间只用于测试计数和状态，不能作为产品速度基准。

### 最小人工评审表

先记录固定流程基线，再填写本次接受的延迟、费用和失败率门槛；不使用未实测的固定收益百分比。

| 合成场景 | 核心检查 |
| --- | --- |
| 前端候选人完整解释 React 项目 | 充分回答后能换题，不机械重复追问 |
| 后端候选人只说“参与了接口” | 澄清亲自完成的部分，不默认核心开发或大规模生产经历 |
| 研究岗位回答误差来源 | 追问岗位相关推理，不强拉回无关技术栈 |
| 教程复现、贡献不清、没有量化数据 | 保留未知和学习边界，不预设性能指标 |
| 反问与请求提示/重答 | 反问先回应再结束；训练帮助可用，模拟不代答 |

逐对记录：问题相关性、是否需要本次追问、是否重复、是否出现无来源假设、关键内容覆盖、用户控制是否有效。出现重大事实补造或退出失效则该案例不通过。其他项目按“更好/相近/更差”并写理由，不用整段固定答案当标准。

只有真实端点的成对质量评审及预算/延迟指标达到事前约定标准，才考虑另行修改默认流程。当前提交保持 fixed 默认，M09 作为可选择的试验能力交付。
