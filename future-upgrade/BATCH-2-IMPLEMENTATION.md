## M06：预算、缓存与有日期的公开证据

主要实现：[GitHub 客户端](../tools/github_client.py)、[项目推荐](../skills/project_recommender/handler.py)、[报告组装](../core/workflow.py)、[配置示例](../config/settings.example.yaml)。

- 使用私有目录中的 `storage/github_cache.db` 缓存公开仓库元数据、README 片段和限流冷却时间，记录抓取日期及来源版本；不缓存档案和 JD。缓存键使用请求摘要，仓库条目经过公开性与字段白名单过滤。
- 分别限制总请求、搜索、README 数量、单次及总下载体积、超时和整轮耗时。默认最多 6 次请求、3 次搜索、2 份 README；不会遍历整个仓库。
- 新鲜缓存直接复用；离线、限流或网络失败时，可在配置的最大陈旧期限内使用带原日期的缓存。默认新鲜期 1 天，最大陈旧期 7 天；过期不能冒充实时结果。
- 区分无权限的 403 和配额/冷却提示，处理 429、Retry-After 与限额重置时间；保存冷却状态，避免重启后反复请求。Token 仍可省略，README 以匿名方式读取，避免将私有内容混入公开缓存。
- 推荐只能引用实际候选仓库，名称、链接、星数、语言及证据由读取结果提供。README 中没有依据的具体文件路径会移除，STAR 始终标为完成任务后才可使用的模板。
- 报告区分 `completed`、`disabled`、`unavailable`、`no_match`、`no_gaps`，补充降级原因、请求数和缓存命中数。GitHub 不可用时，简历主流程继续。

只修改 `settings.example.yaml` 和数据契约的兼容默认，没有修改真实配置。可配置字段见示例中的 `github` 节；`offline: true` 仅关闭 GitHub 请求，**不代表整个定制流程不调用模型**。

## M07：可恢复的面试与请求一致性

主要实现：[共用会话服务](../core/interview_service.py)、[面试存储](../skills/mock_interviewer/session_store.py)、[文件锁](../tools/file_lock.py)、[底层生成与报告](../skills/mock_interviewer/handler.py)。

### 保存和恢复

`storage/interviews.db` 使用独立 schema v1，保存 UUID 会话 ID、岗位/JD、模式、档案快照及摘要、完整问答、运行状态、版本号、模型身份摘要和请求结果。CLI 与 MCP 使用同一服务；MCP 内存字典只保留兼容缓存用途。

开场请求在消费流之前即可恢复。恢复使用原快照，不重新加载当前主档案；修改背景或岗位后应创建新会话。供应商默认沿用原选择，模型或端点配置变化时要求显式传入 provider；不自动更换模型或数据接收端。

仅为空数据库初始化 schema。未知版本、未版本化的既有表和投递数据库会被拒绝，不猜测迁移、不覆盖 `tracker.db`。恢复时验证结构和事实快照摘要。

### 一次作答的边界

1. 在短事务内保存原回答和请求 ID。
2. 使用工作副本流式生成；等待模型时不持有 SQLite 写事务。
3. 完整成功后，原子提交新问题、阶段和结果快照。
4. 流中断或消费取消时保留已接受回答，将请求记为失败；部分问题不进入正式问答。
5. 重试沿用原请求和原回答，不重复登记；已完成请求直接重放。

每个会话使用跨线程、跨进程文件锁，并校验版本，避免并发覆盖或把旧问题的延迟回答附到新问题上。进程意外退出后由操作系统释放锁，pending 请求可重试。不同会话仍可写入数据库。

暂停保留进度，不生成报告。用户明确结束时立即关闭问答；报告失败保留待重试状态，不重新开放作答。复盘只使用正式问答，默认报告请求 `finish` 幂等；重复读取不再调用模型，报告文件丢失时从已存结果重建。显式使用不同报告 ID 会生成独立文件。

### CLI 使用

原有启动命令继续可用。终端会显示会话 ID 和恢复命令：

```powershell
uv run jobhunt interview --resume-session <session_id>

uv run jobhunt interview-sessions list
uv run jobhunt interview-sessions show <session_id>
uv run jobhunt interview-sessions delete <session_id>
```

- `/pause`：保存并暂停；EOF、Ctrl+C 同样暂停。保证保存的是已经提交的回答。
- `/retry`：使用原文和原请求 ID 重试未完成问题。
- `/next`、`/finish` 继续可用；有失败请求时也可明确跳过或结束。
- 恢复沿用原岗位、风格、模式和 JD，不与新的岗位/JD/风格选项混用。必要时使用 `--provider` 明确接受模型配置变化。
- `list/show/delete` 离线执行，不请求模型。查看输出会话及未完成请求，不输出原始档案。删除会话会级联删除快照和请求记录；单独导出的 Markdown 文件保留，需另行删除。

### MCP 兼容

| 原工具 | 新的可选能力 |
| --- | --- |
| `tool_interview_start` | `resume_session_id` 恢复已有会话，不生成新开场 |
| `tool_interview_answer` | `request_id`；`/pause`、`/retry`；返回 revision、暂停和待重试状态 |
| `tool_interview_finish` | `request_id="finish"`；跨重启读取同一报告 |

同一次作答的幂等重试须使用同一个 ID 和完全相同的输入。旧用法不传 ID 仍可工作，但不能识别一次已成功回答的传输重发；需要可靠重试的宿主应提供 ID。回放旧结果不会回退数据库，返回的是当时结果快照，继续新作答前应重新读取当前会话。

开场或追问失败返回 `status="recoverable_error"`，包含会话 ID、待重试 ID 和安全错误类型，不把片段当完整题目。原有成功字段和工具数量保持兼容；`profile://summary` 资源未修改。相关 README 和仓库 Skill 已同步。
